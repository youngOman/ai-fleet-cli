# 派工單:<一句話標題>

> 用法:複製這份到 `$FLEET_TASKS/<名稱>.md` 填好,再 `fleet task <worker> <名稱>`。
> 派工三件套缺一不可:**目標與動機／驗收條件／回報格式**。缺了就補齊再派——
> 缺動機的單子,worker 會照字面做出你不要的東西;缺驗收條件的單子,你沒有辦法說它做完了。

## 第 0 步:先查證(硬性)

動手前先確認這件事**現在還成立**:票是不是已經被關了、程式碼是不是已經改過了、
問題是不是已經不重現了。**已完成就寫報告建議關票,不要重做。**

## 目標與動機

<要達成什麼,以及**為什麼**要做。動機比目標重要——它讓 worker 在遇到你沒預料到的
狀況時,能判斷哪個做法才符合你真正要的。>

## 範圍

- 要動的:<檔案／模組>
- **不要動的**:<明確劃線,例如「不要順手重構隔壁模組」>

## 驗收條件

- [ ] <可客觀判定的條件,例如「`pytest tests/test_login.py` 全綠」>
- [ ] <不要寫「程式碼品質良好」這種無法判定的>

## 回報格式

報告寫到 `$FLEET_REPORTS/<YYYYMMDD-HHMM>-<你的 id>-<主題>.md`,四節缺一不算完成:

1. **做了什麼**(結論先講)
2. **改了哪些檔**(附 `檔案:行號`)
3. **怎麼驗證**(貼指令與**實際輸出**,不是「應該會過」)
4. **殘留問題**
